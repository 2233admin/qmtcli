# 官方数据路径与 Rust 1.99.1 复测（2026-11-01）

[K] 最新稳定版 Rust 1.99.1 已安装并完成同源码回放对照；没有测出相对 1.99.0
的稳定性能提升。JSON 转换和批量处理成本依然存在，不能靠升级编译器消除。
当前测试不是实际 QMT/柜台时延，也没有改变正式 QMTCLI 后端。

## 官方如何处理

依据当前安装的 `bin.x64/Lib/site-packages/xtquant/xtdata.py`，不是猜测 DLL 内部：

| 路径 | 源码证据 | 对性能的含义 |
|---|---|---|
| `get_full_tick`，行 684 | C++ 客户端返回 `resp_json`，Python 调用 `json.loads` | 此路径仍有 JSON 解析；agent 若再输出 JSON，还要重新序列化 |
| `subscribe_callback_wrapper`，行 696 | 回调收到 bytes 时按 BSON 解码，再调用用户函数 | 该分支无需先转 JSON 字符串再解析；不代表完全没有编解码成本 |
| `subscribe_whole_quote`，行 747 | 一个共享客户端接收市场/代码列表及回调 | 大量实时行情走订阅，不必为每个证券反复单独查询 |
| `_get_market_data_ex_ori_221207`，行 494 | `get_market_data3(..., 'v4', ...)` 返回字段缓冲区，`np.frombuffer` 后构造 DataFrame | 部分历史 K 线路径使用数组缓冲区；不能据此宣称最终 DataFrame 完全零复制 |

[官方文档](https://dict.thinktrader.net/nativeApi/xtdata.html) 建议高订阅数量用全推，
单股订阅建议不超过 50；大范围历史请求按需裁剪字段、时间范围，并可从本地数据
读取。**这不是“官方建议每次取 500 条”**，也没有说明固定批量在所有场景最优。
实时推送、历史数组、快照 JSON 是不同接口，不能混为一种传输实现。

[I] 我们可借鉴：常驻订阅和本地状态、只在 agent 边界生成所需 JSON、历史数据
按字段/范围读取。目前 Rust 直连已经避开 SDK full-tick 的中间 JSON→Python
字典转换，但基准中的 BSON Document→JSON 值→字节输出仍有成本。
这些方向尚未作为本轮生产改动或订阅验收实现。

## 最新稳定版核验与公平对照

[Rust 官方 1.99.1 发布说明](https://blog.rust-lang.org/2026/10/15/Rust-1.99.1/)
及 `rustup check` 均确认当前 stable 为 1.99.1（2026-10-15 发布）。
此前本机 stable 为 1.99.0。使用独立 `1.99.1-x86_64-pc-windows-gnu` 工具链，
未修改默认工具链；不是 nightly。`rustc` 提交 `58cf8f9c3`，LLVM 23.1.1。
发布说明列出回归修复，没有承诺此行情路径有普遍性能提升。

- 1.99.0 对照为上轮已保存的 release 二进制；1.99.1 使用相同源码、Cargo.lock、
  GNU target、默认 release 参数构建，没有调整依赖、返回校验或 BSON 复制。
- 复用自有 loopback 回放端与原 Python 适配器；同轮执行两个 Rust、原生 Python
  3.15.2、官方 SDK/Python 3.11.16。每轮轮换顺序并交替反转，预热 2 次。
- 批量为 2/100/500/1000；每个网络/解码条件五组，每组对应计时 300/80/30/30 次。
  单客户端顺序请求，不测并发上限。解码组件只在两个 Rust 上对照。

## 结果

单位 ms，中位数（五组均值最小–最大）；不是单次请求 p50。

| 保留连接，查询加 JSON | Rust 1.99.0 | Rust 1.99.1 | 原生 Python 3.15.2 | SDK / Python 3.11.16 |
|---|---:|---:|---:|---:|
| 2 条 | 0.119 (0.109–0.183) | 0.116 (0.096–0.163) | 0.139 (0.112–0.145) | 0.150 (0.141–0.181) |
| 100 条 | 1.095 (1.073–1.182) | 1.109 (1.087–1.230) | 1.801 (1.765–1.818) | 2.992 (2.970–3.073) |
| 500 条 | 6.071 (5.299–6.236) | 5.616 (5.408–6.650) | 9.093 (8.786–9.210) | 15.043 (15.011–15.291) |
| 1000 条 | 12.838 (12.281–14.411) | 13.620 (13.132–15.522) | 18.818 (18.063–19.042) | 29.856 (29.550–31.210) |

[K] 新旧 Rust 各批量的范围重叠，差值方向也不一致，不宣布编译器升级加速或
回退。1000 条新 Rust 的无 JSON 查询为 11.044 ms (10.579–12.527)，
解码组件为 7.588 ms (7.227–8.439)；旧 Rust 分别 11.437 和 7.301 ms。
新 Rust 1000 条 JSON 的五轮配对额外耗时中位数 2.576 ms，范围 1.082–4.862。
这些组件数据和上轮独立剖析支持继续查解码、对象构造、校验和 JSON 转换成本，
不能由差值精确拆出每个函数的贡献。

[C] 新 Rust 500 条约 11.23 微秒/条，1000 条约 13.62 微秒/条；这是当前合成
回放和当前实现的现象。源码中的 `selected` 对每个返回代码线性扫描选择列表，
显式代码列表下总扫描可达 O(n²)。尚未单独改变匹配结构测量贡献，不能把全部
增幅归因于它，也不能据此固定默认批量为 500。未移除安全校验或改动生产接口。
