# 行情接入消融实验：2026-11-01

[K] 完成连接复用、JSON 输出和批量大小三项消融。固定合成数据、客户端版本、
结果检查及进程生命周期，五轮交错执行。**本轮仍是自有 loopback 回放，不能当作
真实 QMT/柜台延迟。** 没有更换正式后端或降低生产校验。

## 连接复用

同一常驻进程中比较保留会话与每次重建会话，均实际查询并解码，无 JSON 输出。
单位 ms；中位数取五组各自每次操作的平均耗时，括号为组均值范围。

| 客户端／条数 | 保留会话 | 每次重建会话 |
|---|---:|---:|
| Rust／2 | 0.113 (0.088–0.267) | 7.062 (6.411–7.924) |
| Python 3.15.2 原生／2 | 0.132 (0.118–0.203) | 4.554 (2.154–6.214) |
| Rust／1000 | 12.305 (11.809–13.107) | 19.494 (19.266–23.846) |
| Python 3.15.2 原生／1000 | 15.477 (15.132–16.001) | 19.408 (16.749–20.459) |

[C] 2 条小查询中，复用会话的中位耗时分别约为重建的 1/62、1/34。
这是各路径内部的结果；Rust 的实际 `QuoteClient.connect()` 每次会重新读取并
校验五个客户端文件指纹，Python 仅复用已加载 codec 后重新建 socket、认证。
因此不可把 Rust 和 Python 重建列的差值解释为语言或 TCP 握手差异。
两种方式都包含正常 PID 认证、查询、校验；重建方式包含临时 socket 的关闭。
SDK 只作为保留连接参照，没有假设其 reconnect 一定创建新 socket。

[K] 独立的未计时 cProfile 显示，Python 小请求重建路径的主要等待发生在 socket
connect；不是查询数据未执行。Rust 重建路径除了网络还包含上述实际版本核验。
重连耗时随本机调度和 socket 状态波动较大，不能推断真实服务也有同样倍数。

## JSON 输出

每轮相同条数分别执行快照、快照加完整 UTF-8 JSON 序列化；使用实际结果并记录
输出字节数，不把完整 JSON 写入 agent 通道。以下是 **1000 条的每轮配对差值**，
并非两列中位数相减：

| 路径 | 增加的耗时中位数 ms | 五轮范围 ms |
|---|---:|---:|
| Rust release | 1.795 | 1.320–3.308 |
| 原生 Python 3.15.2 | 3.298 | 2.301–4.018 |
| 官方 SDK／Python 3.11.16 | 3.961 | 2.803–4.890 |

[K] 1000 条在每轮都有额外 JSON 成本。2 条场景差值正负不一，与调度噪声接近，
不能给出可靠的微小 JSON 成本。SDK 对整数值浮点数省略 `.0`，1000 条 JSON
382,123 B，另两者 403,123 B；这是各路径当前输出行为，非逐字节等量测试。

[I] agent 可以优先减少重复传输整份快照、减少重复序列化；本轮没有测量增量协议
或不同 JSON 库，因此没有声称这些方案已经获得相应加速。

## 批量大小

以下均为保留连接查询加 JSON，单位 ms，中位数（五组均值范围）。

| 条数 | Rust release | 原生 Python 3.15.2 | SDK／Python 3.11.16 |
|---|---:|---:|---:|
| 2 | 0.123 (0.101–0.166) | 0.130 (0.109–0.173) | 0.157 (0.153–0.192) |
| 100 | 1.243 (1.122–1.431) | 1.894 (1.800–1.973) | 3.324 (3.034–3.507) |
| 500 | 6.049 (5.956–6.671) | 8.822 (8.796–9.059) | 15.246 (14.934–15.555) |
| 1000 | 14.623 (14.099–15.116) | 18.748 (18.302–19.149) | 31.214 (29.407–31.723) |

[C] 从 2 条到 1000 条，按每条摊销的中位耗时，Rust 约从 61.3 降为 14.6 微秒，
原生 Python 从 65.0 降为 18.7 微秒，SDK 从 78.5 降为 31.2 微秒。
这不是实际测量“500 次两条请求”与“一次千条请求”的等工作集调度对照。
批量仍有收益，但不代表越大越好：Rust 500 条约 12.1 微秒/条，1000 条约
14.6 微秒/条。其返回代码校验目前逐结果扫描选择列表，存在随批量增加的扫描成本；
尚未通过单独移除该检查确定其贡献，不能把整段增幅都归因于此。

## 执行、正确性与限制

- 五轮轮换执行顺序、交替反转；所有场景每组预热 2 次。保留路径每组计时次数
  对应 2/100/500/1000 条分别为 300/60/20/15；重建路径每组 10 次。
- 合计 160 个正式计时组、12,250 次计时查询、320 次预热查询。
  服务端共 **12,570 次查询、483 次连接及认证、0 次请求错误**；每组核对预期
  查询增量及连接/认证增量，验证重建实际发生、保留路径没有重复认证。
- 结果检查包含总条数及首条的 18 字段数、Int64 时间戳、五档长度。
  不是全字段逐值语义对账。JSON 实际完整构造并计字节；Rust 消费结果防止无用计算。
- 482 次正常关闭、1 次 SDK 空闲重置分开计数。所有自有进程正常退出。
  独立负控确认半包头、半包体、坏 CRC 三种请求被拒绝，空闲关闭不算请求错误。
- 第一轮预检在 SDK 初始化阶段超时，未进入计时；原始回执保留。
  将未计时的 READY 等待从 40 秒扩为 120 秒后，预检 32 次查询和正式实验均通过。
  超时原因未确定，不归因于周末、QMT 或语言速度。
- 共享主机 32 逻辑核、约 93.7 GiB 内存，开测 CPU 21.1%；其他程序保持运行。
  本轮没有隔离主机或测试并发/长尾。交错只能减轻漂移，不能消除背景噪声。
- 独立 Python 批量 cProfile 再次显示 BSON 递归解码、数组和对象构造占主要调用
  时间；profiler 不在正式计时内，不把其时间占比视为无开销精确归因。
- 此轮未移除返回校验，也未改变 BSON 所有权复制；这两项仍需隔离实验，不能
  宣称已找出全部成本。真实 QMT、订阅、集合竞价及账户四项快照均未测。
